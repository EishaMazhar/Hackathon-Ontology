Hackathon Ontology – SPARQL Demo Queries
===========================================

Namespace prefixes
------------------
Use these prefixes at the top of each query (Protégé SPARQL tab):

PREFIX ex: <http://example.org/ontology#>

------------------------------------------------------------
1) List all hackathons
------------------------------------------------------------
Purpose:
Retrieve all hackathon instances defined in the ontology.

Query:
PREFIX ex: <http://example.org/ontology#>

SELECT ?hackathon ?name
WHERE {
  ?hackathon a ex:Hackathon ;
             ex:name ?name .
}
ORDER BY ?name


------------------------------------------------------------
2) Hackathons with organizing organizations
------------------------------------------------------------
Purpose:
Identify which organizations organized which hackathons.

Query:
PREFIX ex: <http://example.org/ontology#>

SELECT ?hackathon ?organization
WHERE {
  ?hackathon a ex:Hackathon ;
             ex:organizedBy ?organization .
}


------------------------------------------------------------
3) Teams participating in hackathons
------------------------------------------------------------
Purpose:
Show which teams participate in which hackathons.

Query:
PREFIX ex: <http://example.org/ontology#>

SELECT ?team ?hackathon
WHERE {
  ?team a ex:Team ;
        ex:participatesIn ?hackathon .
}


------------------------------------------------------------
4) Teams and their members
------------------------------------------------------------
Purpose:
For each team, list all its members.

Query:
PREFIX ex: <http://example.org/ontology#>

SELECT ?team ?person
WHERE {
  ?team a ex:Team ;
        ex:hasMember ?person .
}
ORDER BY ?team


------------------------------------------------------------
5) Participants and their skills
------------------------------------------------------------
Purpose:
List participants and the skills they possess.

Query:
PREFIX ex: <http://example.org/ontology#>

SELECT ?person ?skill
WHERE {
  ?person a ex:Person ;
          ex:hasSkill ?skill .
}
ORDER BY ?person


------------------------------------------------------------
6) Projects developed during hackathons
------------------------------------------------------------
Purpose:
Show which projects were developed at which hackathons.

Query:
PREFIX ex: <http://example.org/ontology#>

SELECT ?project ?hackathon
WHERE {
  ?project a ex:Project ;
           ex:developedAt ?hackathon .
}


------------------------------------------------------------
7) Projects and contributing teams
------------------------------------------------------------
Purpose:
Identify which teams contributed to which projects.

Query:
PREFIX ex: <http://example.org/ontology#>

SELECT ?project ?team
WHERE {
  ?project a ex:Project ;
           ex:hasContributorTeam ?team .
}


------------------------------------------------------------
8) Number of teams per hackathon
------------------------------------------------------------
Purpose:
Count how many teams participated in each hackathon.

Query:
PREFIX ex: <http://example.org/ontology#>

SELECT ?hackathon (COUNT(?team) AS ?teamCount)
WHERE {
  ?team a ex:Team ;
        ex:participatesIn ?hackathon .
}
GROUP BY ?hackathon
ORDER BY DESC(?teamCount)


------------------------------------------------------------
9) Skill distribution among participants
------------------------------------------------------------
Purpose:
Analyze how skills are distributed across participants.

Query:
PREFIX ex: <http://example.org/ontology#>

SELECT ?skill (COUNT(?person) AS ?count)
WHERE {
  ?person a ex:Person ;
          ex:hasSkill ?skill .
}
GROUP BY ?skill
ORDER BY DESC(?count)


------------------------------------------------------------
Notes:
- Replace the ex: namespace with the actual ontology namespace.
- Queries correspond to the executed query figures in the report.
- Queries are ordered by increasing analytical complexity.
